# Software Supply Chain Security & SLSA Framework

Securing the software supply chain ensures that the code running in production is authentic, untampered, and built exclusively from verified dependencies.

## 1. The SLSA (Supply-chain Levels for Software Artifacts) Framework

| Level | Security Focus | Core Controls Required |
| :--- | :--- | :--- |
| **SLSA Level 1** | Build documentation | Automated build script; provenance metadata generated. |
| **SLSA Level 2** | Tamper-resistance | Hosted build service (GitHub Actions / GitLab CI); signed provenance. |
| **SLSA Level 3** | Hardened build platform | Isolated ephemeral build environments; provenance generated by trusted build service. |
| **SLSA Level 4** | Hermetic builds | Two-party code review; hermetic reproducible builds; dependency pinning. |

## 2. Software Bill of Materials (SBOM) & Attestation
- **SBOM Generation**: Generate machine-readable manifests (SPDX / CycloneDX) during CI builds listing every transitive library and container package.
- **Image Signing**: Sign images using Cosign and Sigstore's Rekor transparency log.
- **Admission Enforcement**: Kubernetes admission controllers verify Cosign signatures before allowing pods to schedule.
