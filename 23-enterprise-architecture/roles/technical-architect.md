# Role Profile: The Technical Architect

The Technical Architect (TA) is a deep technical specialist responsible for software engineering standards, framework design, code structures, and runtime performance within a specific technology domain or platform.

---

## 1. Key Accountabilities
* **Codebase & Framework Architecture**: Define package structures, dependency injection patterns, domain models, and error handling conventions (e.g., in .NET, Java, Python, or TypeScript).
* **Low-Level Design (LLD)**: Author detailed component designs, class hierarchies, database schema definitions, and caching mechanics.
* **Performance & Concurrency**: Profile code execution, optimize thread pools, eliminate memory leaks, and tune query execution plans.
* **Engineering Standards & Guardrails**: Configure static analysis (SonarQube), linter rules, and automated CI/CD test gates.
* **Hands-on Mentorship**: Review pull requests, conduct architecture spikes, build proof-of-concepts, and mentor senior engineers.

---

## 2. Technical Architect vs Solution Architect

| Dimension | Technical Architect (TA) | Solution Architect (SA) |
| :--- | :--- | :--- |
| **Focus** | How the software is engineered and executed internally. | How multiple systems, databases, and APIs integrate to deliver business value. |
| **Coding** | 30%–50% hands-on coding, profiling, and benchmarking. | Primarily architectural modeling, interface contracts, and design validation. |
| **Primary Artifact** | Framework scaffolds, schema DDL, low-level design specs. | Solution Architecture Documents (SAD), cloud deployment models. |
