# Value Stream Mapping Principles

Rules for identifying, defining, and optimizing enterprise value streams.

---

## 1. Core Principles of Value Stream Architecture

1. **Outside-In Perspective**: Value streams exist for the customer or beneficiary, not for the internal IT department or organizational hierarchy.
2. **Sequential Value Progression**: Every stage must demonstrably add value and advance the state of the entity (e.g., from *Applicant* to *Approved Applicant* to *Funded Borrower*).
3. **Explicit Trigger and Value Outcome**: Every value stream begins with a clear business event trigger and concludes with a measurable business outcome.
4. **Measure Flow Metrics**:
   * **Lead Time (Total Elapsed Time)**: Wall-clock time from trigger to outcome.
   * **Processing Time (Active Work Time)**: Time actually spent performing value-add work.
   * **Flow Efficiency**: $\text{Flow Efficiency} = \frac{\text{Processing Time}}{\text{Lead Time}} \times 100\%$. (In un-architected enterprises, flow efficiency is often <5% due to batch queues and manual handoffs).
