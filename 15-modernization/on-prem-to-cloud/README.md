# On-Premises to Cloud Migration Architecture Playbook

## 1. Overview
Migrating an enterprise portfolio from on-premises datacenters to public cloud (AWS, Azure, Google Cloud) requires disciplined discovery, wave planning, landing zone foundations, hybrid connectivity, and automated migration tooling.

## 2. Directory Structure
- [cloud-migration-playbook.md](cloud-migration-playbook.md): The end-to-end cloud migration lifecycle.
- [portfolio-discovery-and-inventory.md](portfolio-discovery-and-inventory.md): Automated asset discovery and dependency mapping.
- [migration-wave-planning.md](migration-wave-planning.md): Grouping applications into sequenced migration waves.
- [cloud-landing-zone-readiness.md](cloud-landing-zone-readiness.md): Multi-account structure, IAM, network, and security guardrails.
- [hybrid-connectivity-and-vpn.md](hybrid-connectivity-and-vpn.md): Dedicated private interconnects (Direct Connect / ExpressRoute).
- [migration-factory-model.md](migration-factory-model.md): Enterprise Migration Factory operational model.
- [validation-and-testing-in-cloud.md](validation-and-testing-in-cloud.md): Acceptance, performance soak, and DR testing in cloud.
- [cloud-cutover-and-dns-switch.md](cloud-cutover-and-dns-switch.md): High-stakes cutover execution and DNS traffic shift.
- [post-migration-finops-optimization.md](post-migration-finops-optimization.md): Cost rightsizing, reserved instances, and FinOps guardrails.
