# API Error Handling (RFC 7807 Problem Details)

## 1. The Standard: `application/problem+json`
Modern enterprise APIs standardize on **RFC 7807** to provide machine-readable, consistent error descriptions across all microservice boundaries.

```json
{
  "type": "https://api.enterprise.com/errors/insufficient-funds",
  "title": "Insufficient Account Balance",
  "status": 422,
  "detail": "Account balance of $42.50 is insufficient for requested debit of $100.00.",
  "instance": "/v1/accounts/acc_9921/transfers/tx_102",
  "invalid_params": [
    {
      "name": "amount",
      "reason": "Must not exceed available balance ($42.50)"
    }
  ]
}
```

---

## 2. Universal RFC 7807 Attributes
* `type` (URI): Unique identifier classifying the error type.
* `title`: Human-readable summary of the problem type.
* `status`: HTTP status code generated by origin server.
* `detail`: Human-readable explanation specific to this occurrence.
* `instance` (URI): Relative URI pointing to the specific operation failure.
