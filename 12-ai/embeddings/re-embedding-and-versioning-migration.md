# Re-Embedding & Vector Versioning Migration Architecture

## 1. The Incompatibility of Embedding Spaces

A critical architectural invariant: **Vectors from different embedding models (or different versions of the same model) CANNOT be compared**.

You cannot search a vector space generated by `text-embedding-ada-002` using a query vector generated by `text-embedding-3-small`. Upgrading an embedding model requires a **complete re-embedding migration of the entire document corpus**.

## 2. Migration Best Practices
1. **Always Preserve Raw Text in S3**: Never treat the vector database as the primary source of truth. Always preserve the raw text of chunks in high-durability object storage so re-embedding pipelines can re-read source documents directly.
2. **Dual-Writing during Migration**: Inbound new documents must be embedded by both the old model (for immediate searchability) and the new model (to populate the blue index).
